# Deploying PDF Analyzer

The app deploys as **one free Render web service**: the Express server runs the API and also serves the built React website. The database stays on MongoDB Atlas.

```
Browser ──> https://pdf-analyzer.onrender.com ──> Express ──> MongoDB Atlas
                       (website + /api)                   └──> Gemini API
```

Why one service instead of Vercel + Render: with two different domains, browsers such as Safari block the login cookie as a "third-party cookie", so users could not stay logged in. One domain avoids that.

## What you need

- A **GitHub** account with this project pushed to a repository (private is fine).
- A **Render** account (render.com). Sign up with GitHub, no card needed for the free plan.
- Your **MongoDB Atlas** connection string and **Gemini API key** (the same ones in `server/.env`).

## Step 1 - Allow Render to reach MongoDB Atlas

Render's free plan has no fixed IP address, so Atlas must accept connections from anywhere (your password still protects the database).

1. Atlas → **Network Access** → **Add IP Address**.
2. Click **Allow access from anywhere** (`0.0.0.0/0`) → **Confirm**.

## Step 2 - Create the service on Render

1. Render dashboard → **New** → **Blueprint**.
2. Connect GitHub and pick the `pdf-analyzer` repository. Render reads `render.yaml`.
3. Render asks for the values marked `sync: false`:

   | Variable | Value |
   |---|---|
   | `MONGO_URI` | Same as in `server/.env` |
   | `GEMINI_API_KEY` | Same as in `server/.env` |
   | `CLIENT_URL` | Your Render URL, e.g. `https://pdf-analyzer.onrender.com` (you can fill this in after the first deploy) |

   `NODE_ENV`, `AI_PROVIDER`, `AI_MODEL` are set by `render.yaml`. `JWT_SECRET` is generated by Render automatically - do not reuse your local one.

4. Click **Apply**. The first build takes 2-4 minutes. Watch the **Logs** tab for:

   ```
   [db] Connected to MongoDB (pdf-analyzer)
   [server] Running on http://localhost:10000
   ```

5. Open the URL Render shows (e.g. `https://pdf-analyzer.onrender.com`) and sign up.

If the logs show `Missing environment variables: ...`, add that variable under the service's **Environment** tab and redeploy.

## Updating the live site

Push to the `main` branch on GitHub - Render rebuilds and redeploys automatically.

## Things to know about the free plan

- **Sleeps when idle:** after 15 minutes without visitors the service sleeps; the next visit takes ~50 seconds to wake it up. A paid instance ($7/month) stays awake.
- **750 free hours/month:** enough for one service running all month.
- **Gemini free tier:** rate-limited and Google may use the data for training. Switch to a paid model before real users arrive (change `AI_PROVIDER` / `AI_MODEL` in Render's Environment tab).

## Local development is unchanged

```bash
cd server
npm run dev
```

```bash
cd client
npm run dev
```

`client/.env.development` points the dev website at `http://localhost:5000`; production builds ignore that file.

## Test a production build locally (optional)

```bash
npm run build
```

Then start the server in production mode on another port (PowerShell):

```powershell
$env:NODE_ENV="production"; $env:PORT="5050"; npm start
```

Open http://localhost:5050.
